# 위키 운영 규칙

이 문서는 `/Users/hyerimjeong/Obsidian/IvyPath/wiki`를 Karpathy style LLM Wiki로 관리하기 위한 규칙이다.

## 핵심 구조

1. `raw/`는 원문 보관층이다. 질문 답변, PDF 추출본, 사용자 원문, 회의록처럼 나중에 다시 검증해야 할 자료를 둔다.
2. `sources/`는 원문 요약층이다. raw 파일을 읽고 어떤 기억을 만들었는지 요약한다.
3. 주제별 폴더는 컴파일된 wiki다. `people/`, `brand/`, `students/`, `curriculum/`, `content/`, `sales/`가 여기에 해당한다.
4. `_index.md`는 사람이 읽는 지도다. 새 페이지를 만들거나 의미가 바뀌면 함께 갱신한다.
5. `_log.md`는 변경 이력이다. ingest, 정리, 정책 변경, 큰 방향 수정이 있을 때 날짜와 목적을 남긴다.

## 편집 원칙

1. raw에 없는 사실을 새 브랜드 주장처럼 추가하지 않는다.
2. 원문에 있는 표현을 우선 재구성한다.
3. 요약과 판단은 sources 또는 compiled wiki에 둔다.
4. raw 파일은 가능한 한 수정하지 않는다.
5. 기존 Obsidian wikilink 형식을 유지한다.
6. frontmatter의 `type`, `tags`, `aliases`, `source`는 가능한 보존한다.
7. 인물, 브랜드, 학생, 커리큘럼, 콘텐츠, 세일즈를 섞지 않는다.

## 새 자료 ingest 절차

1. 새 원문을 `raw/`에 저장한다.
2. raw 파일명은 날짜와 주제를 포함해 만든다.
3. 해당 raw를 요약하는 `sources/` 페이지를 만든다.
4. source 페이지에서 영향을 받는 compiled wiki 페이지를 연결한다.
5. 관련 `people/`, `brand/`, `students/`, `curriculum/`, `content/`, `sales/` 페이지를 필요한 만큼만 갱신한다.
6. `_index.md`에 새 페이지를 추가한다.
7. `_log.md`에 작업 기록을 남긴다.

## 품질 점검

1. 링크가 끊기지 않았는지 확인한다.
2. 같은 기억이 여러 페이지에 중복 저장되지 않았는지 확인한다.
3. 원자료와 다른 과장 표현이 들어가지 않았는지 확인한다.
4. 현재 브랜딩 가드레일과 충돌하는 문구가 없는지 확인한다.
5. 팀원이 GitHub에서 pull했을 때 Obsidian에서 바로 읽을 수 있는 구조인지 확인한다.
